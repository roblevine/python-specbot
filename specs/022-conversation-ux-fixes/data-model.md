# Data Model: Conversation UX Fixes

**Feature**: 022-conversation-ux-fixes
**Date**: 2026-01-22
**Status**: No changes required

## Overview

This feature uses the **existing data model** with no modifications. The required `updatedAt` field is already present in the Conversation entity.

## Existing Entities (Reference Only)

### Conversation

The conversation entity already includes all fields needed for this feature:

```javascript
{
  id: "conv-xxxxx",           // Unique identifier
  title: "Conversation Title", // Display title
  createdAt: "2026-01-22T10:30:00.000Z",  // ISO8601 creation timestamp
  updatedAt: "2026-01-22T15:45:00.000Z",  // ISO8601 last activity timestamp ← Used for sorting & display
  messages: [...]             // Array of messages
}
```

**Key Field for This Feature**: `updatedAt`
- Used for sorting conversations (most recent first)
- Displayed as timestamp subtext in conversation list
- Already updated automatically when:
  - Conversation is created
  - Message is added
  - Title is renamed
  - Title is generated by LLM

### Message

No changes to message entity. Reference only:

```javascript
{
  id: "msg-xxxxx",

  sender: "user" | "system",
  timestamp: "2026-01-22T15:45:00.000Z",
  status: "pending" | "sent" | "error",
  model: "gpt-4"  // Optional, for system messages
}
```

## New Component State (Frontend Only)

### InputArea Focus State

New local state within `InputArea.vue` component:

```javascript
// Not persisted - component-local reactive state
const hadFocusBeforeSend = ref(false)
const inputRef = ref(null)  // Template ref for textarea
```

**State Transitions**:
1. On message send: `hadFocusBeforeSend = (document.activeElement === inputRef.value)`
2. On click outside input: `hadFocusBeforeSend = false`
3. On response complete: if `hadFocusBeforeSend`, restore focus

## Validation Rules

No changes to existing validation rules. All fields validated in `frontend/src/utils/validators.js`.
