# Feature Specification: LLM-Generated Conversation Titles

**Feature Branch**: `019-llm-conversation-titles`
**Created**: 2026-01-21
**Status**: Draft
**Input**: User description: "At the moment the title of a conversation is the first line of the request. I now want to change this so that the first request and response are themselves passed to an LLM with an instruction to come up with a succinct title. To do this, we need another operation (possibly on the conversations endpoint? discuss) which takes a partial conversation and creates the title. Each model provider should now identify what the default title model is. So for instance, if I am using any OpenAI models, but GPT-3.5-Turbo is specified as the default title model, then this is the model that should be used when requesting a conversation title. i.e. the endpoint itself expects you to tell it the model to use, the client selects the default for that provider. If none is configured as conversation title default, it will use the current selected model."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Automatic Title Generation After First Exchange (Priority: P1)

A user starts a new conversation and sends their first message. After receiving the assistant's response, the application automatically generates a meaningful, concise title that summarizes the conversation topic without requiring any user action.

**Why this priority**: This is the core feature - replacing the current behavior of using the first message text with an intelligently generated title that provides better context at a glance.

**Independent Test**: Can be fully tested by sending a first message in a new conversation and verifying that the title changes from "New Conversation" to a relevant, succinct summary after the assistant responds.

**Acceptance Scenarios**:

1. **Given** a new conversation with the default title "New Conversation", **When** the user sends a message and receives a response, **Then** the conversation title is automatically updated to a succinct summary generated by an LLM.

2. **Given** a conversation that already has a user-set or previously generated title, **When** additional messages are exchanged, **Then** the title remains unchanged (no re-generation on subsequent messages).

3. **Given** a new conversation, **When** the title generation request fails (e.g., network error), **Then** the title falls back to the first user message text and an error is logged (not displayed to user).

---

### User Story 2 - Provider-Specific Title Model Configuration (Priority: P2)

An administrator configures which model should be used for generating conversation titles for each provider. This allows using a fast, cost-effective model for title generation while using more capable models for actual conversations.

**Why this priority**: Enables cost optimization and ensures consistent title generation behavior. Without this, every title generation would use the potentially expensive conversation model.

**Independent Test**: Can be tested by configuring a title model for a provider and verifying that title generation requests use the configured model instead of the current conversation model.

**Acceptance Scenarios**:

1. **Given** a provider has a configured title model (e.g., `gpt-3.5-turbo` for OpenAI), **When** a title generation is requested for a conversation using any model from that provider, **Then** the configured title model is used for generation.

2. **Given** a provider has no configured title model, **When** a title generation is requested, **Then** the currently selected conversation model is used for generation.

3. **Given** multiple providers are configured with different title models, **When** the user switches between providers, **Then** the appropriate title model for each provider is used.

---

### User Story 3 - Title Generation Endpoint (Priority: P1)

The system provides an operation to generate a conversation title from conversation content. The client specifies which model to use, enabling flexibility in model selection based on provider configuration.

**Why this priority**: This is the technical foundation for Story 1 - the endpoint must exist before automatic title generation can work.

**Independent Test**: Can be tested by calling the endpoint directly with conversation messages and a model ID, verifying a title is returned.

**Acceptance Scenarios**:

1. **Given** a valid request with conversation messages and model ID, **When** the title generation endpoint is called, **Then** a succinct title (maximum 60 characters) is returned.

2. **Given** an invalid model ID, **When** the title generation endpoint is called, **Then** an appropriate error is returned.

3. **Given** empty or missing conversation messages, **When** the title generation endpoint is called, **Then** an appropriate error is returned.

---

### Edge Cases

- What happens when the LLM returns an excessively long title? The system truncates to a maximum of 60 characters.
- What happens when the conversation contains only special characters or non-text content? The system handles gracefully and provides a generic title like "New Conversation".
- What happens when the user manually renames a conversation and then continues the conversation? Manual titles are preserved and not overwritten.
- What happens when title generation takes too long? A reasonable timeout applies, with fallback to the first message text.
- What happens when the configured title model is not available? The system falls back to the current conversation model.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST provide an operation to generate a conversation title from conversation content and a specified model ID.
- **FR-002**: System MUST accept the first user message and first assistant response as input for title generation.
- **FR-003**: System MUST generate titles that are succinct (maximum 60 characters) and descriptive of the conversation topic.
- **FR-004**: System MUST support configuring a default title model per provider via configuration.
- **FR-005**: Client MUST select the appropriate title model based on the current conversation's provider: use the provider's configured title model if available, otherwise use the currently selected model.
- **FR-006**: System MUST NOT regenerate titles for conversations that already have a non-default title (either user-renamed or previously generated).
- **FR-007**: System MUST fall back to using the first message text as the title if title generation fails.
- **FR-008**: System MUST preserve manually set titles and never overwrite them with generated titles.
- **FR-009**: System MUST return generated titles in a timely manner, with appropriate timeout handling.
- **FR-010**: System MUST validate that the requested model ID exists and is available before attempting title generation.

### Key Entities

- **Title Model Configuration**: A per-provider setting that specifies which model to use for title generation. Stored in environment configuration alongside existing model settings.
- **Title Generation Request**: A request containing conversation messages (at minimum the first user message and first assistant response) and a target model ID.
- **Title Generation Response**: A response containing the generated title string.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Generated titles accurately reflect the conversation topic in at least 90% of cases (measured through user feedback or title change rate).
- **SC-002**: Title generation completes within 5 seconds for 95% of requests.
- **SC-003**: Users can identify conversation topics from titles without opening the conversation in at least 80% of cases.
- **SC-004**: System handles title generation failures gracefully with zero user-facing errors (falls back to message text).
- **SC-005**: Configuration of title models requires only environment variable changes with no code modifications.

## Assumptions

- The existing conversation and model infrastructure supports adding a new operation for title generation.
- LLM providers (OpenAI, Anthropic) can reliably generate short, descriptive titles when prompted appropriately.
- A prompt such as "Generate a succinct title (max 60 characters) for this conversation" will yield appropriate results.
- The first message-response pair provides sufficient context for meaningful title generation.
- Title generation can be performed asynchronously without blocking the user's conversation flow.
- The cost of title generation (using a smaller/cheaper model) is acceptable for each new conversation.
